# ワイド予算戦略プレイブック

> `--budget` `--type` `--points` `--ev-threshold` を受け取って買い目と点数を最適化する方法論。
> A・B 共用を想定。Phase 4 で共通モジュール化する。

## 1. 概要

競馬の買い目戦略は **券種選択 × 軸馬選定 × 相手選定 × 予算配分** の 4 軸で決まる。本プレイブックは「期待値ベース」での予算最適化フレームを示す。

> **注意**: 期待値が 1.0 を超えると数学的には買う方が得だが、的中までの分散が大きいため、**長期で続けて初めて回収率に収束**する。短期の的中・不的中で評価しないこと。

## 2. 券種別の妙味比較

| 券種 | 期待値出しやすさ | 分散 | 推奨用途 |
|---|---|---|---|
| 単勝 | △（控除率 20%） | 中 | 軸馬への確信度高い時 |
| 複勝 | △（控除率 20%、オッズ低い） | 低 | 安定収益を狙う時 |
| ワイド | ○（3 着までで的中） | 中 | **本命党のメイン券種** |
| 馬連 | ○（控除率 22.5%） | 中-高 | 軸 - 相手の組合せ妙味 |
| 馬単 | △（控除率 22.5%、点数嵩む） | 高 | 軸馬の勝ちパターン明確時 |
| 三連複 | ◎（妙味出しやすい） | 中-高 | **穴を絡めた時の妙味券種** |
| 三連単 | △（控除率 27.5%、点数嵩む） | 非常に高 | 配当狙いの少額勝負 |

**推奨**: 軸 1 頭流しのワイド or 三連複が、本命型予想と相性が良い。

## 3. 期待値計算の基本フレーム

### 3-1. 想定的中確率の算出

各馬の **想定勝率** を 5 段階で評価：
- ◎ 本命（想定勝率 25-35%）
- ○ 対抗（15-25%）
- ▲ 単穴（10-15%）
- △ 押さえ（5-10%）
- ▽ 穴（3-5%）

各馬の **想定連対率（2着以内）** は、勝率 × 1.7 〜 1.8 倍が目安。
**想定複勝率（3着以内）** は、勝率 × 2.4 〜 2.6 倍。

> ⚠️ **この換算表は未校正の暫定値**。実績（predictions/ の発走前確定予想 × score_prediction.py の
> 採点結果）が貯まったら「◎の実際の勝率・複勝率」と照合して数値を更新する。
> 校正の母集団規約は `predictions/README.md` を参照（発走前確定のみ・バックフィル予想は使わない）。
> 校正前の EV 判定は「目安」であり、EV 数値の見かけの精度を信用しない。

### 3-2. 期待値の計算

```
期待値 = 想定的中確率 × オッズ
```

**期待値 1.2 以上を「買い妙味あり」と判定**（控除率を考慮するとこのライン以上が長期回収率プラスの目安）。

### 3-3. ワイド・三連複の組合せ計算

ワイド `A — B` の的中確率 ≒ A の複勝率 × B の複勝率（独立性の近似）
三連複 `A — B — C` の的中確率 ≒ 上記の拡張

> **正確には**：A と B の同時的中は独立ではない（同じレースなので）。実務では **JRA 公式の理論オッズと実際オッズの乖離** を見るのが現実的。

## 4. 予算配分の方法論

### 4-1. ベースライン: 確信度配分
本命確信度に応じて予算を傾斜配分。

| 軸の確信度 | 軸馬中心配分 | 例（予算 3000円） |
|---|---|---|
| 5（鉄板） | 軸 60% / 相手 30% / 穴 10% | ワイド ◎-○▲ 1800円 + ◎-△ 600円 + ◎-▽ 300円 + 三連複 300円 |
| 4 | 軸 50% / 相手 35% / 穴 15% | ワイド主軸を分散 |
| 3 | 軸 40% / 相手 40% / 穴 20% | 軸固めしすぎない |
| 2 以下 | レース見送り or 少額のお試し | 1000円以内 |

### 4-2. 期待値配分（上級）
各組合せの期待値 × 想定的中確率 で予算を傾斜配分。
詳細は Phase 4 で実装する Python モジュール（`scripts/wide_optimizer.py` 仮）に組み込む予定。

擬似コード：
```python
def optimize_budget(candidates, budget, ev_threshold=1.2, max_points=8):
    # candidates: [{combo, expected_odds, prob, ev}, ...]
    candidates = [c for c in candidates if c["ev"] >= ev_threshold]
    candidates = sorted(candidates, key=lambda c: c["ev"], reverse=True)[:max_points]
    total_ev = sum(c["ev"] * c["prob"] for c in candidates)
    return [
        {**c, "amount": int(budget * (c["ev"] * c["prob"]) / total_ev / 100) * 100}
        for c in candidates
    ]
```

### 4-3. 最低単位
JRA は **100 円単位**。点数を増やしすぎて 100 円割れになる場合は、点数を絞るか予算を上げる。

## 5. 引数仕様

`/recommend --budget=3000 --type=wide --points=6 --ev-threshold=1.2` の解釈：

- `--budget`: 総予算（円）
- `--type`: 券種（`win` / `place` / `wide` / `umaren` / `umatan` / `sanrenpuku` / `sanrentan`）。複数指定 `--type=wide,sanrenpuku` も検討
- `--points`: 点数上限。指定なしなら期待値順で自動決定
- `--ev-threshold`: 期待値しきい値（既定 1.2）

## 6. 買い目テンプレート

### 6-1. 軸 1 頭流し（本命確信度高い時）

ワイド: ◎ — ○▲△ （3 点、配分は本命相手の信頼度で傾斜）
三連複: ◎ — ○▲△ — ○▲△▽ （6-9 点）

### 6-2. 軸 2 頭ボックス（軸が並立）

ワイド: ◎○ ボックス（1 点、配分大きめ）
三連複: ◎○ — ▲△▽ — ▲△▽（複数点）

### 6-3. 穴狙いミックス

ワイド: ◎ — ○▲△ + ▽ — ○▲ （穴のワイドを軽め）
三連複: ◎ — ▲△ — ▽ （穴を含めた組み合わせ）

### 6-4. シナリオ整合の原則（2026 安田記念の反省）

買い目をペースシナリオに対応づけて検算する。**「保険」はそのシナリオで台頭する馬で組む**。

- 対抗シナリオ（例: Sl・前残り）を明記したら、**そのシナリオで生き残る買い目が最低1点** あるか確認する。
  Sl の保険なのに差し馬同士のワイド、は保険になっていない（2026 安田記念: Sl シナリオ的中・
  逃げた△が2着に残ったのに、保険ワイドが差し系 9-16/9-3 で全滅）。
- 連系の **2列目の柱は「全シナリオ横断で最頻出の馬」** を置く。単一シナリオでしか上位に来ない
  ○に2列目を寄せると、その馬が沈んだだけで複数点が同時に死ぬ。
- 検算手順: 各シナリオ（M/Sl/Hi）について「このシナリオの 1-3着想定」を書き、
  買い目リストと突き合わせて **どのシナリオで的中ゼロになるか** を明示する。
  的中ゼロのシナリオが確信度2以上なら配分を見直す。

### 6-5. 買い目に入れる馬の決め方（2026 セントライト記念の反省）

**印を付けた馬を、印より弱い理由で買い目から落とさない。**

1. **EV 順で入れる**。自分の分析で算出した期待値が ◎ を上回る馬は、原則として買い目に含める。
   外す場合は **EV を再計算して閾値を下回ることを示す**。「的中率優先」「人気薄だから」は理由にならない。
   - 2026 セントライト記念: ▽7 を「EV 1.3〜1.5（◎の1.15より上）」と自分で書きながら買い目から除外 →
     その 7 が1着（12番人気50.6）。三連複 2-6-7 = 32,610円、回収率 0%。
2. **「予算都合」を除外理由に使わない**。点数固定（例 1000円÷100円=10点）の買い方では、
   ある馬を入れても点数は変わらない。点数が変わらないのに外したなら、**本当の理由は別にある**
   （人気薄を買う心理的抵抗）。理由を言語化してから判断する。
3. **BOX は脚質を分散させて初めて BOX**。組んだ買い目の構成馬について
   **脚質（逃げ/先行/差し/追込）を数える。同一脚質が過半数なら、それは「軸を割った」ことになっていない**。
   - 2026 セントライト記念: 5頭BOX のうち 8/9/10 の3頭が後方待機。Sl 決着で3頭同時に崩れ全滅。
   - 対処: 過半数を占める脚質があるなら、1頭を別脚質（先行・逃げ絡み）に差し替える。
4. **穴を入れる枠を最初から確保する**。均等買いでは「人気サイド N 点＋穴絡み M 点」と
   先に枠を決めてから中身を埋める（後から穴を足そうとすると必ず削られる）。
5. **穴は「◎との2頭券」で持つ。三連系1点だけで「買い目に入れた」ことにしない**（2026 凱旋門賞の反省）。
   三連複1点の的中確率は1%前後で、穴馬が激走しても3頭目が揃わなければ0円になる。
   ワイド等の2頭券を買うなら、EV 上位の穴は **◎ との2頭券で最低1点** 持つ。
   `validate_output.py` の `_check_marked_horse_only_in_trio` が warn を出す。
   - 2026 凱旋門賞: 初版（200円×5点）は ▽7 Bay City Roller を三連複 1-7-15 の1点だけで「買い目入り」としていた。
     7 が13番人気で2着に来たが、3着は 15 ではなく 16 で、初版の回収率は 0%。
     改訂版（100円×10点）で足したワイド ◎1-7 が 2,560円 となり、回収率 256%
6. **2頭目の軸は「根拠が検証済みか」で選ぶ**。未検証の一般論（例: 「ロンシャンは内枠有利」）だけを根拠にした馬に、
   10点中6点を寄せない（2026 凱旋門賞: ○15 を2頭目の軸にして6点を寄せ、15 は8着。この6点がすべて外れた）。

## 7. 検証フレーム（実装済み・運用ルール）

実際の予想の採点は `scripts/score_prediction.py`（predictions/ の md × DB の results/payouts）で行う。

> ⚠️ **ルックアヘッド汚染ガード**: 「過去レースに予想パイプラインを走らせて回収率を測る」
> バックテストは **行わない**。LLM はカットオフ以前のレース結果を学習済みのため、
> 過去レースへの「予想」は後知恵が混入し、回収率は無意味に高く出る。
> 有効な検証は **発走前に git commit した予想の事後採点のみ**（predictions/README.md の規約）。
> 過去データの正しい用途は集計の母数（産駒成績・コース傾向・ペース分布）に限る。

## 8. 守るべきガード

- **賭博助言ではない**: 出力は予想と買い目の参考情報。最終判断はユーザー責任
- **資金管理**: 1 レースあたりの予算は **総資金の 1-3%** を超えない（プロでも 5% 超は危険）
- **追い掛け禁止**: 負けたレースの直後に予算を増やすのは破滅パターン
- **連敗期間の認識**: 期待値 1.2 でも 10 レース連続外しもあり得る分散
- **券種ミックス**: 1 レースに全予算を 1 券種に投じない（保険として 2-3 券種）
